## 1. 测试架构

因环境中无 puppeteer / jsdom，自建最小 CDP 客户端：

- **`tests/cdp.js`**：raw WebSocket 实现（帧掩码、文本帧分片处理），`Browser.launch()` 启动 `--headless=new --remote-debugging-port`，`Page.evaluate()` 执行脚本，并收集 `Runtime.exceptionThrown`（→ `pageErrors`）与 `console.error`（→ `consoleErrors`）。
- **`tests/fixture.js`**：从 `_debug/Qw71Alf.html`（真实问卷页面存档）用花括号匹配抽取 `topic` 为 6/3/31/4/5/223/15/7 的 `.field` 原文，组装成测试问卷。**不是手写假 DOM**，题型属性、`verify`、`relation`、`gapfill` 均为真实值。
- 复刻的 WJX 协议（依据 `jqmobo2.js` 实际绑定）：
  - 单选/多选：`.checked` + `.jqchecked` 双标记 toggle
  - 矩阵：`a.rate-off` → `rate-on` 类切换 + `dval`
  - 填空：`keyup`/`blur`/`click` → `verifyTxt` + `saveAnswer`
  - 填空组：`span.textCont` blur 写回前一 `input.value`
  - 内嵌填空：`blur`/`keyup` → 保存
  - 关联题：按 `relation` 重算 `style.display`
  - `checkIDCard`：从 `jqmobo2.js` **逐字复制**，含原始错误文案

### 5.1 排查记录

首次运行 12/15。3 项失败原因：**测试间状态污染**——前一组留下的 `WJX_AUTOMATION_STOPPED` 标志在同一个浏览器 profile 内被后一组继承，导致「有会话也不续跑」，进度弹窗不显示。

修法：在暂停组开始前显式 `localStorage.removeItem('WJX_AUTOMATION_STOPPED')` 并重新加载。

**这是测试隔离缺陷，不是脚本缺陷**——停止标志跨刷新持久化恰恰是设计意图（第 7 条断言验证的正是这一点）。

## 5.5 分页测试 · 44 项全部通过（0.1.20 新增）

测试文件 `tests/pagination.test.js`，fixture 为 8 道基础题 + 25 份复制单选块 = **33 道题 / 4 页**。

设计重点：分页最容易引入的不是 UI 问题，而是**配置静默丢失**——`collectCurrentQuestionsFromDom` 若以「DOM 里的卡片」为准重建配置数组，分页后 DOM 只有当前页 10 张卡，任何 `syncStateFromDom` + `saveConfig` 都会把其余 23 题从 `localStorage` 抹掉。所以本套件前半部分专测「翻页不影响配置」。

| 分组 | 断言数 | 关键验证 |
|---|---:|---|
| 1. 面板定位 | 3 | `position === 'fixed'`；对标题栏派发 mousedown/mousemove/mouseup 后位移 `dx===0 && dy===0`（不是只看 CSS 声明） |
| 2. 分页 UI 基本行为 | 14 | 默认 10 卡、总页数 4、列表 `overflowY==='auto'`、底部 CTA 常驻可见、页码输入与上一页/下一页按钮行为 |
| 3. 翻页不丢配置 | 8 | 翻到第 3 页再翻回，`localStorage` 里的配置仍有全部 33 题；某题权重改成 `777` 后跨页往返仍是 `777` |
| 4. 一键随机覆盖全部页 | 4 | 分页状态下点「一键随机全部」，未渲染页的题目也被重算（`zeroAmongThem.length === 0`） |
| 5. 每页条数切换 | 3 | 10 / 20 / 50 / 200 切换后卡片数与总页数正确 |
| 6. 筛选与分页联动 | 5 | 改筛选自动回第 1 页；无匹配时给明确空态；标题旁「已匹配 x / y 道」 |
| 7. 折叠行为 | 5 | 折叠后 body 隐藏、footer CTA 一并隐藏、按钮文案变「展开」 |
| 8. 无控制台错误 | 2 | 全程无未捕获异常、无 `console.error` |
| **合计** | **44** | |

### 5.5.1 排查记录（重要）

首轮运行多个断言失败，且现象互相矛盾（第 3 页第 1 题报的 qid 是 `6`、配置编辑被折叠）。根因不在脚本，在 fixture 生成器：`repeatRadio` 用**双引号**做属性替换（`/topic="6"/g`），而问卷星导出的 HTML 是**单引号**（`topic='6'`）——替换全部静默失配，25 份复制块的题号全都是 `6`。测的其实是「同一个题号的 26 张卡」，不是「26 道不同的题」。

改为单引号替换后全绿。**同一个缺陷此前也存在于 `tests/scale.test.js`**，导致历史「147 题」性能数据的题数标签失真，已在 6.1 节标注并重测。

## 6. 性能测试

方法学：每轮**全新页面**（避免 JIT 预热与残留全局）、**交替执行顺序**、多轮取**中位数**。

### 6.1 与上游原版对照（同 fixture）

两套测量分别由不同脚本产出，数据不可混用：

**规模曲线**（`tests/scale.test.js 7`，7 轮中位数，仅测「注入 → 面板渲染完成」）：

> 数据更新说明（0.1.20 复测）：此前这组数据是 3 轮中位数，且 `repeatRadio` 用双引号做属性替换——问卷星导出的 HTML 是单引号（`topic='6'`），替换全部静默失败，140 份复制块的题号全是 `6`。也就是说旧表里的「147 题」实际是「148 个同题号的 DOM 块」，测的是渲染耗时而非多题识别；题数标签也少算了 1（基础 fixture 是 8 题，不是 7）。现已修正为单引号替换并核对卡片数，同时把轮数提到 7 轮以提高置信度。

| 题数 | 本项目 2.0.0 | 上游 4.1.4 | 比值 | 本项目渲染卡片数 | 上游渲染卡片数 |
|---|---|---|---|---|---|
| 8 | 21.4 ms | 9.8 ms | 2.18x | 8 | 8 |
| 28 | 26.3 ms | 14.6 ms | 1.80x | 10 | 28 |
| 68 | 25.9 ms | 20.7 ms | 1.25x | 10 | 68 |
| 148 | 31.4 ms | 40.5 ms | **0.78x** | 10 | 148 |

**读法**：小问卷（8 题）本项目慢约 11 ms，这是 15 个全局按钮 + 每题 4 个快捷操作 / 16 项筛选 / 卡片级配置的固定成本，不是复杂度问题；随题数增长本项目曲线基本走平（21.4 → 31.4 ms），上游线性上升（9.8 → 40.5 ms），**在 148 题时本项目反超为更快**，原因是列表分页后渲染卡片数恒定为 10 张。交叉点落在 68–148 题之间。

**多轮交替测量**（`tests/perf.test.js 5`，5 轮交替执行顺序取中位数，8 题 fixture）：

| 指标 | 本项目 | 上游 4.1.4 |
|---|---|---|
| 执行耗时中位数 | 35.2 ms（样本 94.5 / 67.3 / 35.2 / 30.2 / 25.6，首轮为冷启动离群值） | 11.3 ms |
| DOM 节点增量 | 383 | 207 |
| 空闲 1.5s 后节点增长 | 0 | 0–2 |

**判定：接近线性，无复杂度问题。** 规模曲线上本项目 8→148 题只增加 10 ms，上游增加 31 ms；两条曲线的差异是功能密度与渲染策略差异，不是算法退化。

### 6.2 DOM 差异溯源

| 指标 | 本项目 | 上游 | 差异来源 |
|---|---|---|---|
| DOM 增量 | 383 | 207 | 41 个功能按钮（13 个全局 + 每题 4 个快捷操作 vs 上游 0 个）+ 66 DIV + 19 OPTION（筛选器 16 项（含「全部题型」）vs 3 项）+ 分页控件 |
| 空闲 1.5 s 后节点增长 | 0 | 0–2 | 无 DOM 泄漏 |

**结论：差异来自功能密度，不是冗余，不予精简。**

### 诚实结论

**161 项断言全覆盖通过与「脚本在线上可用」是两件事。** 本次测试能证明的是：

1. 脚本在**忠实复刻的 WJX DOM 与事件契约**下填写正确；
2. 修复的缺陷有可复现的回归测试，其中 1 个做过反向验证；

**不能证明**的是：串接真实问卷星后端时的表现。第 7 节列出的 12 项均需在授权测试问卷中人工复验。
