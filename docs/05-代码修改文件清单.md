## 一、修改的既有文件

### `问卷星.js`（+126 行 / −28 行，v2.0.0 → 2.0.1）

| 位置 | 改动 | 原因 |
|---|---|---|
| 头部 5–7 行 | `@version` 2.0.0 → 2.0.1；新增 2.0.1 `@updateLog` | 版本发布规范 |
| `init`（约 1205 行） | `injectStyles()` 提到 `isCompletionPage()` 判定之前 | 完成页弹窗的外观定义在 `STYLE_TEXT` 里，旧顺序下弹窗 `position: static`、背景透明 |
| `injectStyles`（约 1400 行） | 加 `style[data-wjx-panel]` 幂等保护 | 提前注入后会被重复调用，不加保护会重复插入 `<style>` |
| `refreshQuestions`（约 1774 行） | `previousTargetCount` 只在 `preserveInputs` 为真时读 DOM；先写回份数再算提示 | **核心修复**：初始化时输入框是模板默认 `value="1"`，无条件读 DOM 会把存档份数覆盖成 1 |
| `updateCountModeHints`（约 2427 行） | 删除 `State.config.targetCount = getCurrentTargetCount()` | 同上：本函数先于「写回份数」执行，回写会把存档份数打回 1；份数以 `State.config.targetCount` 为权威 |
| `clearCurrentSurveyStorage`（约 3189 行） | 刷新界面后再 `removeItem` 一次 | 刷新会触发自动随机 + `saveConfig`，刚清掉的存档立刻被写回 |
| `extractQuestionId`（约 3883 行） | 临时查询（`fallbackOrder === 0`）改用题目在页面中的稳定序号 | 扫描时存 `fallback:1`、填写时算 `fallback:temp`，两处永不相等 → 无 id/topic 的题被静默跳过 |
| `readNumericBound`（新增，约 4093 行） | 按 `minword`/`maxword` → `min`/`max` 顺序取边界 | 问卷星把数字题范围写在 `minword`/`maxword` 上，旧实现只读标准属性，取不到就退化成 0–99999 |
| `generateValueForRequirement`（约 4113 行） | number 分支改用 `readNumericBound`；`min>max` 以 `min` 为准 | 同上；并保证 `randomInt` 区间合法 |
| `pickMultipleIndices`（约 5481 行） | 0 权重保持 0；优先从正权重抽，不足时才回落零权重 | 旧实现 `Math.max(1, w)` 把 0 抬成 1，用户配的 0 完全失效 |
| `getMatrixRowIndexBase`（新增，约 6355 行） | 按整题最小 `rowindex` 判断 0 起 / 1 起 | 真实存档三份（`Qw71Alf` / `desktop_page` / `mobile_page`）都是 0 起 |
| `getMatrixQuotaRowIndex`（约 6374 行） | 改为 `Math.floor(parsed) - offset` | 旧实现 `parsed > 0 ? parsed - 1 : parsed` 把 `0..9` 映射成 `0,0,1,…,8`，第 1、2 行共用配额行 |
| `fillMatrix`（约 6405 行） | 传入整题基准值 | 同上 |

## 二、新增文件

### `tests/persist.test.js`（约 130 行）

真实 Chrome + `localStorage` 的持久化回归，9 项断言，覆盖两类纯逻辑测试不可能发现的缺陷：

1. 份数刷新被模板默认值覆盖（输入 37 → 刷新 → 仍是 37，且再次保存不被打回 1）
2. 清除本地数据后配置被自动随机写回（清除后 `localStorage` 必须为空）

| 模块 | 理由 |

| `detectType` 题型判定链 | 11 类题型识别已在真实页面验证正确，**不做重构** |
