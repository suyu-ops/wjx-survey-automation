## 它凭什么敢称最强

不是自封。下面四条，每一条都能在仓库里点到具体文件、具体测试，或复跑同一条命令验证。

### 一、调研范围内，唯一做到「事件契约级」正确的实现

调研到的同类脚本大多靠「把 `.value` 写进去」来填空，界面上看是填好了，**提交时却仍被判「未作答」**。原因是问卷星前端把答案存在自己维护的答案表里，DOM 值只是显示层。

本脚本的做法是先把问卷星自己的前端脚本（`jqmobo2.js`）里的事件绑定逐条读出来，再按原样复刻写入序列：

| 控件 | 问卷星真实绑定 | 只写 `value` 的脚本 | 本脚本 |
|---|---|---|---|
| 文本输入 | `keyup blur click` → `verifyTxt` + `saveAnswer` | ❌ 界面有值、答案表为空 | ✅ `focus` + `input`/`change` + `keyup` + `blur` 全派发 |
| 选项内嵌填空 | `blur keyup`，其中 `keyup` 走 `otherTextEvent` | ❌ 看着填上、提交报未作答 | ✅ 同步进选项对象 |
| 矩阵评分 | `a.rate-off` → `rate-on` + `dval` | ❌ 星级不亮 / 值不落库 | ✅ 点 `a[dval]` 本身，由页面自己切 `rate-on` 并写 `dval` |
| 填空组（`span.textCont`） | `blur` 时回写到前一个 `input.value` | ❌ 只改显示层 | ✅ 走 blur 回写 |
| 单选 / 多选 | `a.jqradio` / `a.jqcheckbox` + `jqchecked` 标记 | ⚠️ 只点外层 `li`，可能不触发页面回调 | ✅ 依次尝试 `a.jqradio` / `label` / `input`，每步校验选中态再继续 |

这是 0.1.16 / 0.1.18 / 0.1.19 三个版本连续踩坑踩出来的结论，每一条都有对应的回归测试。

### 二、调研范围内，唯一能表达「我要 30% 选 A」的实现

横向扫了三个同类项目，答案分布能力是这样的：

- 上游原版：粗粒度权重 + 份数
- `MingNin9466/survey-autofill-helper`：模板固定值，**没有分布控制**
- `DreamYuande/wjx-question-bank-collector`：只采集题目、不填写
- 本脚本：**比例模式 + 次数模式双轨**，占比题按 `total` 约束分配并自动补齐取整误差，关联题联动重扫最多 8 轮

### 三、题目越多，它反而越快

题目列表在 0.1.20 改成「列表内独立滚动 + 分页」后，渲染卡片数**恒定 10 张**，不再随题数增长。

同一套 fixture、7 轮中位数、注入到面板渲染完成：

| 题数 | 本脚本 | 上游原版 4.1.4 | 渲染卡片数（本 / 上游） |
|---:|---:|---:|:--:|
| 8 | 21.4 ms | 9.8 ms | 8 / 8 |
| 28 | 26.3 ms | 14.6 ms | 10 / 28 |
| 68 | 25.9 ms | 20.7 ms | 10 / 68 |
| **148** | **31.4 ms** | 40.5 ms | 10 / 148 |

小问卷慢的十几毫秒，是 15 个全局按钮 + 每题 4 个快捷操作（8 题 fixture 实测 47 个 `button`）与 16 项筛选下拉的固定成本；题数一多，上游线性爬升，本脚本曲线走平——**148 题时反超**。

### 四、把“填错了”当成 bug 来修，而不是当成概率

- 身份证号按 **GB 11643** 真算加权校验码，实测生成 500 个号码 **500/500** 通过问卷星自身的 `checkIDCard`
- 填空题按 `verify` 属性（而不是 `input type`）判定格式，度数题不会再被当成手机号塞 11 位随机数
- 弹层类题目（多级下拉、地区）识别不了就**明确跳过并提示「需手动选择」**，绝不写一个页面不认的假值蒙过去
- 配额耗尽、内嵌框写不进去、配额回滚失败，一律 `logWarning` 显式报出，不吞
- 连续 2 次提交仍卡在人机验证，自动暂停并提示换网络，而不是继续空撞把风控等级撞高

> 以上全部结论的调研过程、平台可达性、以及无法访问的站点最终改用什么途径取证，都记在 [`docs/02-竞品调研报告.md`](docs/02-竞品调研报告.md)；跑不过的地方也一并写在那儿。

## 它不做什么（比功能列表更重要的部分）

一个敢说自己最强的脚本，必须先把边界说清楚：

- **不做验证码识别。** 遇到滑块 / 点选只做模拟交互，失败就停，不接第三方打码平台。
- **不绕过平台风控。** 连续 2 次提交仍卡人机验证就自动暂停，提示换网络或等待冷却——而不是把风控等级撞得更高。
- **不伪造提交结果。** 提交失败就是失败，不会假装成功往下走。
- **不做「填上了但页面不认」的假成功。** 写不进去就 `logWarning` 报出来，绝不静默当通过。
- **不联网。** 全文 0 处 `fetch` / `XMLHttpRequest` / `sendBeacon` / `GM_*` 调用；面板内外部链接只有三处（题库入口、OCS 说明、QQ 群），且都要用户自己点。问卷内容、答案、配置一样都不上传。
- **不收费、不插广告、不做邀请裂变。** MIT 许可，永久免费，赞赏纯自愿且不影响任何功能。

## 功能特性

### 题型支持 · 11 类全覆盖

问卷星 `type` 属性里的 11 种题型全部识别（`1`/`2` 文本、`3` 单选、`4` 多选、`5` 评分、`6` 矩阵、`7` 下拉、`8` 滑块、`9` 填空组、`11` 排序、`12` 占比，外加 `location` 地区题），每种都有独立的填写路径——不是「一个 `fillText` 打天下」：

| 题型 | 关键处理 |
|---|---|
| 单选 / 多选 | `a.jqradio` / `a.jqcheckbox` 点击 + `jqchecked` 双标记；遵循 `minvalue` / `maxvalue` 配额 |
| 下拉选择 | 原生 `select` 赋值 + `change` |
| 填空（文本） | 按 `verify` 细分 **数字 / 号码 / 身份证 / 邮箱** 四类，面板各自标注，避免格式错填 |
| 填空组 `gapfill` | 「\_\_年\_\_月\_\_日」逐空格单独配置，走 `span.textCont` blur 回写 |
| 评分星级 | `a.rate-off` → `rate-on` + `dval`，星级视觉与取值同步 |
| 矩阵题 | 桌面版与手机版（`v.wjx.cn`）行结构差异分别适配，按 `tr[rowindex]` 精确取行 |
| 占比题 | 读题目 `total` 作为合计目标，按权重分配并把取整误差补到最大项，同步 `rangeslider` |
| 滑块题 | 拖动模拟 + 取值范围配置 |
| 排序题 | 按点击顺序逐项选中，识别 `sortnum` 状态，遵循 `minvalue` / `maxvalue` |
| 地区选择 | 识别弹层选择类，写不进就明确提示手动 |
| 选项内嵌填空 | 「（请填写）xx」复合题，**逐选项**配置填写内容 |
| 未知题型 | 显式标记为「未知题型」并在面板提示，不猜测、不静默跳过 |

> 身份证号按 **GB 11643** 计算第 18 位加权校验码（权重 `7 9 10 5 8 4 2 1 6 3 7 9 10 5 8 4 2`，映射 `1 0 X 9 8 7 6 5 4 3 2`）。生成 500 个号码，500/500 通过问卷星自身的 `checkIDCard`。

### 配置能力

- **双模式**：比例分配（按权重随机）/ 数量配额（按次数逐一分配），面板内一键切换
- **关联题联动**：子题随父题选项变化自动重扫，单次填写内最多 8 轮（`fillAllQuestions` 的 pass 循环），直到没有新题被填上
- **多页问卷自动翻页**：问卷本身分页时自动翻页填写，`MAX_AUTO_PAGES` 上限 80 页（未在真实多页问卷验证，见测试说明）
- **题目分页**：面板内题目列表默认 10 题/页，可切 10 / 20 / 50 / 200，支持翻页与页码输入跳转
- **列表内独立滚动**：题目多也不会把整个面板撑长，底部「开始自动化提交」常驻可见
- **搜索与筛选**：关键词搜索 + 15 项题型筛选（另有「全部题型」，含数字 / 号码 / 身份证 / 邮箱四个填空细分），与分页联动（改筛选自动回第 1 页，标题旁显示「已匹配 x / y 道」）
- **配置导入 / 导出**（JSON），换设备、换问卷都能带走
- **固定定位**：右上角 `position: fixed`，不可拖动——避免在多页问卷里被误拖到屏幕外且拖不回来
- **速度档位**：慢速 / 正常 / 快速，快速档带绝对下限，不会压到触发风控
- **逐题快捷操作**：每题卡片固定 4 个——随机（按题型给默认偏向）/ 恢复本题 / 复制到同类题 / 暂不自动填写

### 自动化会话

- **预览填写**：只高亮所选答案、不提交，可逐题核对
- **预览选答计划**：不开填，先看这一轮会选哪些项
- **填写到提交**：填满全部题目并提交
- **会话控制**：暂停 / 继续 / 跳过 / 停止，进度弹窗实时反馈
- **失败恢复**：配额快照 + 回滚，中途失败不会让份数凭空少掉
- **风控自保**：连续 2 次提交仍卡人机验证 → 自动暂停并建议换网络，而不是继续空撞

### 健壮性

- **258 个具名函数 · 7,024 行单文件**，`@grant none`，**零外部依赖**（不引 CDN，断网也不掉样式）
- **43 处 `try`（38 `catch` + 6 `finally`）**，7 处空 `catch` 全部落在 `localStorage` / `document.cookie` / `console` 这类确实无可恢复动作的位置
- **未知题型、弹层题、填入失败一律显式提示**，不静默当成功
- **无 DOM 泄漏**：空闲 1.5 秒后节点增长为 0

### 资源与反馈

- 面板内提供 [星夜题库](https://tiku888.top/) 入口：千万免费题库，支持 OCS 网课助手接入
- [OCS 接入说明](https://tiku888.top/guide) 在新标签页打开
- 标题栏 QQ 群反馈入口，问题与建议直接提
- 所有外链均需用户主动点击，不传递问卷内容或本地配置

## 使用

1. 打开问卷星问卷页面（桌面版或手机版均可），右上角出现配置面板
2. 面板自动识别题目并逐题列出，先在「全局设置」里定份数与分配模式
3. 逐题配置答案分布（比例或次数），题目多时用搜索 / 筛选 / 翻页定位
4. 不确定就先点「预览填写」核对高亮结果
5. 确认后点「填写到提交」开始自动化，过程中可暂停 / 跳过 / 停止

配置自动按问卷 URL 存进 `localStorage`，同一份问卷下次打开直接接着用；换问卷互不干扰。

## 配置说明

| 配置项 | 说明 |
|---|---|
| 设计份数 | 本次要提交的问卷份数；超过 100 份时面板会提示分批执行 |
| 分配模式 | **比例**：各选项数值为权重比例；**数量**：各选项数值为选中次数 |
| 速度档位 | 慢速 / 正常 / 快速，控制动作间隔与翻页节奏；快速档有绝对下限保护 |
| 逐题权重 | 每张题卡上的选项数值，两种模式下含义不同（面板会实时提示） |
| 预览填写 | 只高亮所选答案，不提交，可逐题核对 |
| 预览选答计划 | 只算不填，先看这一轮的选答结果 |
| 填写到提交 | 自动填写全部题目并提交 |
| 导出 / 导入配置 | JSON 快照，含全部题目权重与文本答案库 |
| 一键随机全部 | 按当前模式重算**全部**题目（含未渲染的其他页） |
| 复制到同类题 | 把当前题的选项结构复制给选项一致的同类题 |
| 恢复默认配置 | 丢弃当前问卷的改动，按页面重新扫描 |
| 清除本地数据 | 清本脚本配置 + 问卷星作答残留（`wjxanswerdata`、`wjxgguid` 等）+ 脚本可写的设备标识 Cookie |

> 面板内的**翻页、搜索、筛选状态不写入配置**，换页不会触发保存，也不会被当成「配置已修改」。

## 测试与验证

**161 项自动化断言，全部通过。** 不是「手点了几下没问题」，是真的跑在真 Chrome 里：

| 套件 | 断言数 | 覆盖内容 |
|---|---:|---|
| 单元 | 65 | 分配算法不变量 720 组、身份证校验、格式过滤、关联解析、洗牌、权重选择边界 |
| 集成 | 26 | 真 Chrome + 复刻的 WJX DOM/事件契约，逐题型填写正确性，连续 4 轮稳定 |
| 健壮性 | 11 | 空页面、畸形 DOM、缺属性、超长题号、未知题型不崩 |
| 生命周期 | 15 | 会话开始/暂停/继续/停止/跳过的状态机、配额快照回滚 |
| 分页 | 44 | 翻页不丢配置、一键随机覆盖全页、筛选联动、折叠行为、固定定位回归 |
| 性能 | 2 组 | 规模曲线 + 多轮交替测量 + DOM 泄漏检测 |

实现上**没有引入 puppeteer / jsdom**，测试用自己写的 CDP 客户端（`tests/cdp.js`）直接驱动 Chrome 原生 WebSocket —— 少一层依赖，就少一层「测试通过了但其实测的是模拟环境」。

**反向验证过**：把内嵌填空的修复临时回退到旧的事件序列，测试立刻失败；恢复后重新通过。断言不是恒真的。

## 风险提示

> ⚠️ **本脚本明确包含两项「负面特性」，请先读这段再决定是否安装：**
>
> - **自动批量提交**：按设定份数循环填写并提交。这会显著增加目标问卷的作答量，可能触发问卷星平台风控（人机验证、限流、封禁）。若目标问卷有「一台设备/一人一份」的限制，批量提交会污染它的数据。
> - **生成式随机答案**：填空题与文本题按词库随机生成内容，可能造成低质量、无意义或重复的回答。
>
> **请仅在获得授权的问卷中使用**（自己的测试问卷、明确知情的内部调研等），遵守问卷发起方与平台的使用条款。拿它去刷别人的问卷、填充虚假样本、污染公开调研数据——那是滥用，不是本项目的意图，责任自负。
>
> 本项目以 MIT 许可发布，不提供任何形式的可用性担保。使用前请自行评估合规风险。

| 0.1.20 | 面板重做与题目分页。① **视觉重构**：按设计稿重做面板（标题栏品牌图标、渐变统计卡、分段式分配模式控件、深色题库卡片、常驻底部主 CTA），全部用纯 CSS 实现，不引入 Tailwind CDN —— 脚本是 `@grant none`，引外部样式表会在断网/CDN 被墙时整块面板失去样式。② **固定定位**：移除 0.1.1 引入的拖拽逻辑与 `_PANEL_POSITION` 位置记忆，改回纯 `position: fixed` 右上角；可拖动在多页问卷里经常被误拖到屏幕外且拖不回来。③ **题目分页**：题目列表改为「列表内独立滚动 + 分页控件」，默认 10 题/页，支持每页条数（10/20/50/200）、上一页/下一页、页码输入直接跳转，并与搜索/题型筛选联动（改筛选自动回第 1 页、标题旁显示「已匹配 x / y 道」、无匹配给明确空态）。实测 148 题时面板渲染 31.4ms、渲染卡片数从 148 张降到恒定 10 张，此时已快于上游原版（40.5ms，7 轮中位数）。④ **分页安全改动**：`collectCurrentQuestionsFromDom` 改为模型驱动 —— 旧实现「以 DOM 卡片为准重建配置数组」，分页后 DOM 只有当前页卡片，任何 `syncStateFromDom` + `saveConfig` 都会把未渲染页的配置从 `localStorage` 静默抹掉；现在以 `State.config.questions` 为骨架，只覆盖当前 DOM 中存在的卡片的可编辑字段。⑤ **同源缺陷修复**：`randomizeAllQuestions` 旧实现遍历 DOM 卡片，分页后「一键随机全部」只随机当前页，其余题的旧值会一直带到提交；改为按模型遍历全部题目并回写已渲染卡片。父子排序也从「按卡片排序」改为「按模型关联深度排序」——卡片排序在分页后找不到父题，数量模式下会让子题按父题旧值算次数 |
| 0.1.19 | 修复选项内嵌填空（复合题）写不进答案表：问卷星给 `input.OtherText` / `input.OtherRadioText` 绑定的是 `blur keyup` —— `keyup` 走 `otherTextEvent` 把值同步进选项对象，`blur` 才调用 `saveAnswer`。此前这里只派发 `input`/`change`，界面看着填上了、答案表里却是空的，提交时该题仍被判「未作答」；现在统一复用 `writeTextInput`（`focus` + `input`/`change` + `keyup` + `blur`），与填空题保持同一套事件序列。同时补上两处调用点的返回值检查：内嵌框写不进去时用 `logWarning` 报出来，不再静默当作成功。配额回滚 `withQuotaRollback` 的读取/恢复失败也从空 `catch` 改为 `logWarning`，避免份数凭空减少却查不到原因。清理从未被读写过的 `optionTexts` 字段（实际使用的是 `optionFills`） |
| 0.1.18 | 修复身份证题与填空组（出生日期）填不上。① 身份证号第 18 位是 GB 11643 加权校验码，此前生成器「前 17 位随机、末位随便写」，11 次里有 10 次会被问卷星的 `checkIDCard` 判「请输入正确的身份证号」；现在按国标真算校验码（年份取 1975-2003、日取 1-28，避开页面年份正则与非法日期），候选内容也改用完整校验而非仅判 18 位格式，实测生成 500 个号码 500/500 通过问卷星自身的校验函数。② 填空题只派发 `input`/`change`，而问卷星在 `input` 上绑定的是 `keyup blur click`（`verifyTxt` + `saveAnswer`），导致界面有值但页面未校验、未存答案；现在补齐 `focus`/`keyup`/`blur`。③ 填空组（`type=9` / `gapfill`，如「出生日期：__年__月__日」）未被调用的根因是按题号 `find` 配置时不比对题型：升级后旧配置里遗留的 `unknown` 条目抢先命中、走到 `default` 分支返回 `false`，页面即报「请回答此题」；现在同步时清理同题号的过时题型条目，并让查找同时匹配页面实际题型 |
| 0.1.17 | 填空题按校验类型细分显示：此前所有 `text` 题型在面板上一律标为「填空题」，号码题（`verify='手机'`）虽已正确填入 11 位号码、数字题虽已按数值填充，但从面板看不出脚本会写什么；现在标签按 `textRequirement` 显示为「号码题 / 数字题 / 身份证题 / 邮箱题」，卡片副标题给出「按手机号格式填充」等说明，题型筛选新增这四个细分项。同时补上弹层选择类题目处理：问卷星的「多级下拉」（`verify='多级下拉'` + `input[readonly]` + `onclick=openCityBox`）校验的是弹层内部选中状态，直接写 `value` 只会留下页面不认的假值、提交时仍报未作答；现在扫描时标记 `pickerBased`，填写时跳过并在面板提示「需手动选择」，避免静默填错掩盖问题 |
| 0.1.16 | 修复填空题按 `input type` 猜格式导致的错填：度数题（`verify='数字'` 但 `type='tel'`）此前被当成手机号，生成 11 位随机数字，用户配置的「11/12/13」被完全丢弃；现在按 `verify` 属性判定校验类型（数字 / 手机 / 身份证号 / 邮箱 / 文本），候选内容先按该格式过滤、符合则优先使用，全不符合时才按格式生成，面板在填空题卡片上显示当前校验类型提示。同时新增「选项内嵌填空」复合题支持：问卷星把「（请填写）两」这类选项写成 `.ui-radio > .ui-text(display:none) > input.OtherRadioText`，此前点击后写死填「其他」且不等输入框显示，导致该类题被判未作答；现在扫描时为每个带内嵌框的选项生成可配置项，面板提供逐选项输入框（按单位生成默认值、参与「随机」与「复制到同类题」），选中后等输入框显示再写入并派发 `input`/`change`/`blur`，留空则不填 |
